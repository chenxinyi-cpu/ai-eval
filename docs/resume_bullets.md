# 简历项目描述草稿

## 项目 A：接口自动化测试与 CI 回归框架 (api-auto-test)
**一句话定位**：基于 Pytest + Requests 的多环境接口自动化框架，数据驱动设计，接入 CI 流水线与性能压测。

**核心简历 Bullet（选 3 条）：**
1. **架构设计与解耦**：设计 YAML 数据驱动的接口用例框架，将测试数据与底层 HTTP 封装分离。新增接口用例无需改动代码，提升用例编写效率。
2. **鉴权与状态管理**：封装 requests Session，统一处理 BaseURL、环境变量、Token 注入及请求异常拦截。利用 Pytest Session 级 Fixture 实现一次登录全局复用，避免重复鉴权开销。
3. **CI/CD 工程化落地**：接入 GitHub Actions 实现持续集成。Push 触发拉取代码，启动 FastAPI 被测后端并做健康检查，就绪后执行冒烟测试并留存 Allure 测试报告。
4. **Mock 隔离与边界测试**：结合 responses 库拦截 HTTP 请求，演示依赖隔离。明确区分服务级 Mock 与代码级 Mock 的适用场景，验证“Mock 通过不等于集成正确”的测试盲区。
5. **性能基线测试**：使用 Locust 对核心登录接口进行并发压测，输出 QPS、P50/P95 响应时间与错误率，为服务性能提供基础水位数据。

**局限**：仅做接口功能校验，不替代探索性测试；对频繁变动的接口维护成本较高。

## 项目 B：LLM 自动化评测与质量回归平台 (ai-eval-hub)
**一句话定位**：面向大模型输出的质量验收平台，采用“多指标 + LLM-as-judge”交叉验证，并接入 CI 实现版本迭代的自动回归阻断。

**核心简历 Bullet（选 3 条）：**
1. **交叉评测体系设计**：设计 YAML 驱动的评测流程，融合 BLEU/ROUGE 及基于 BERTScore 的语义相似度计算，并引入大模型裁判（LLM-as-judge）按 Rubric 进行事实与完整性打分，解决单一指标无法评估事实正确性的痛点。
2. **双视角 Badcase 归因**：实现指标与 Judge 的双视角 Markdown 报告。将 Badcase 精细划分为“确认问题”、“指标误判（语义相似但事实错）”与“指标盲区”三类，并输出 Judge 判断理由，大幅提升人工排查效率。
3. **CI 自动化门禁与基线追踪**：接入 GitHub Actions 定时评测。通过 `actions/cache` 缓存历史评测数据，实现跨流水线的版本基线对比。当指标显著下跌（如跌幅超 5%）时，自动返回非零退出码（`sys.exit(1)`）阻断 CI 并触发告警。
4. **大模型输出稳定性保障**：针对 LLM 裁判的幻觉和非结构化输出，实现强制 JSON 格式约束、Markdown 剥离解析及超时重试机制，保障了评测流水线的稳定性。

**局限**：当前阈值与 Rubric 为基线默认值，实际落地需结合业务场景校准；裁判模型调用成本较高，全量执行需评估 ROI。
