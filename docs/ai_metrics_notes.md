# AI 评测指标笔记

## BLEU
- 衡量：n-gram 精确率（生成文本有多少出现在参考中）
- 适合：机器翻译等输出应与参考高度重合的任务
- 缺点：对同义替换极不友好。

## ROUGE
- 衡量：n-gram 召回率（参考有多少被生成覆盖）
- 适合：摘要等不能漏信息的任务
- 缺点：同样只看字面。

## BERTScore
- 衡量：token 语义向量的余弦相似度
- 优点：对同义替换宽容。
- 缺点：语义相似 ≠ 事实正确，事实错误但用词相近时可能给高分。

## 今天的观察与踩坑记录
1. **中文分词坑**：直接用 evaluate 算中文的 BLEU/ROUGE，分数全是 0.0。因为底层按空格分词，中文需要做额外的分词处理。
2. **BERTScore 的效果**：同义改写得到 0.8651 的高分，语义相反得到 0.7581。证明了 BERTScore 确实能衡量语义相似度，但“语义相反”依然有较高分数（盲区），说明不能只依赖这一个指标判断质量。
3. **环境踩坑**：
   - 加载 bert_score 需要手动装依赖。
   - 国内直连 HuggingFace 卡顿，配置了 `HF_ENDPOINT="https://hf-mirror.com"` 解决。
   - 下载的本地 `bert-base-chinese` 存在 `max_length` 缺省导致 C++ 层溢出的 bug，通过 Python 打补丁强改为 512 解决。

## 对项目B的启示
- 单一指标不够，必须组合使用。中文场景要引入分词机制。
- 事实正确性需要 LLM-as-judge 或人工复核。
- 指标层应该解耦，后续接入项目B时需要屏蔽这些环境差异，提供统一的 compute 接口。
